# MP3CutAd-RS GUI 使用说明

基于 egui 的跨平台音频广告检测 + 事件分类 + HPSS 源分离工具。

---

## 1. 界面概览

```
┌─────────────────────────────────────────────────────────────────────┐
│ MP3CutAd-RS  │ 添加文件 │ 检测广告 │ HPSS 分离 │ 📂模型│🎯分类│... │ ← 顶部工具栏
├──────────────┬──────────────────────────────────────────────────────┤
│ 左侧文件列表  │  中央结果面板（音频条 + 事件轨道 + 图例）              │
│              │                                                      │
├──────────────┴──────────────────────────────────────────────────────┤
│ 底部状态栏：进度条 / 当前状态 / 文件数 / 阈值设置                    │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 快速上手指南

### 2.1 基本广告检测流程

1. **添加文件** — 点顶部 `添加文件` 选单个或多个音频，或 `添加目录` 批量导入
2. **（可选）启用 HPSS** — 勾选工具栏 `HPSS 分离` checkbox（对带背景音乐的广告段更稳定）
3. **检测广告** — 点 `检测广告` 按钮，进度条实时更新
4. **查看结果** — 检测完成后，中央面板展示每个文件的广告段彩色区间
5. **裁剪保存** — Ctrl+点击广告段（或 `按匹配度选择` 批量选中）→ 点 `删除所选` 标记要裁剪的段 → 点 `保存` 写回

### 2.2 事件分类流程（第一期新增）

事件分类需要先训练一个 `.mcrf` 模型文件。CLI 训练方法见本文档末尾。

1. **选择模型** — 点 `📂 模型: xxx.mcrf` 按钮 → FileDialog 选 `.mcrf` 文件
   - 文件名会显示在按钮上，方便确认当前加载的模型
   - 即时验证文件合法性，损坏的模型会弹错误提示
2. **分类事件** — 点 `🎯 分类事件` 按钮，对列表中所有文件运行分类
   - 状态条显示进度：`[2/5] 正在分类 xxx.wav`
3. **查看事件轨道** — 每个文件的广告段音频条下方会出现**独立事件轨道**：
   - 冷色调边框矩形（浅蓝/浅绿/橙黄/淡紫…每种标签一个颜色）
   - 宽度足够的段显示 `标签名 置信度%`
   - 窄段只显示置信度
4. **图例说明** — 顶部标题栏右侧自动出现 `🎯 事件 ▢ 纯音 ▢ 噪声` 图例

### 2.3 HPSS 分离流程（第三期新增）

HPSS（Harmonic-Percussive Source Separation）基于中值滤波将音频拆为：
- **谐波轨道**：连续音调（音乐、说话声）
- **打击乐轨道**：宽带瞬态（鼓点、音效、广告 jingle）

检测阶段用打击乐轨道替代原始音频做匹配，可显著削弱背景音乐干扰。

1. **勾选 HPSS 分离** — 工具栏 `HPSS 分离` checkbox
2. **点检测广告** — 状态条显示 `HPSS 分离中 1/3: xxx.mp3`
3. **检测结果更干净** — 带背景音乐的广告段匹配度通常更高

> HPSS 会让检测耗时增加约 2-3 倍（需额外 STFT + 中值 + iSTFT）。
> 缓存版本号已升至 2.0，启用 HPSS 后旧缓存会自动失效（下次检测重新计算）。

### 2.4 组合工作流（推荐）

```
添加文件 → 勾选 HPSS → 检测广告 → 📂选模型 → 🎯分类事件 → 审核 → 删除所选 → 保存
```

## 3. 控件详解

### 3.1 顶部工具栏

| 按钮/控件 | 说明 |
|-----------|------|
| 添加文件 | FileDialog 选 mp3/wav/flac/m4a/aac/ogg/opus/wma |
| 添加目录 | 递归扫描目录下所有支持格式 |
| 检测广告 | 对列表文件跑 LSH + Viterbi 广告检测 |
| HPSS 分离 | ⚙️ **开关** — 启用打击乐轨道源分离 |
| 📂 模型: xxx.mcrf | FileDialog 选 `.mcrf` 分类模型，即时验证加载 |
| 🎯 分类事件 | 对所有文件运行滑窗分类 + 事件合并 |
| 按匹配度选择 | 打开筛选窗口，按高/中/低置信度或自定义下限批量选择广告段 |
| 全选广告 | 选中所有满足阈值的广告段（批量删除用） |
| 取消全选 | 清空选中列表 |
| 删除所选 (N) | 标记选中段为删除（时间轴压暗画红斜线，需点保存才真正写入文件） |
| 覆盖原文件 | ✅ 直接覆盖，❌ 输出到同目录 `_cut.mp3` 新文件 |
| 保存 | 按标记裁剪并组合剩余片段 |
| 清空列表 | 重置所有状态 |
| 阈值设置 | 右侧面板展开/折叠匹配度分色阈值 |

### 3.2 中央结果面板

文件过滤逻辑：显示**已检测** OR **已分类** OR **有事件**的文件。

#### 每个文件展示区域

```

  ■ 10.0-18.5s 92%    ■ 45.0-52.0s 78%    ■ 120.0-128.0s 88%
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 事件轨道（冷色调边框）
  ┌─纯音 98%─┐                                ┌─噪声 72%─┐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 时间刻度
  0s     30s     60s     90s    120s    150s    180s    210s
```

#### 状态图标

| 图标 | 含义 |
|------|------|
| ✓ | 仅检测广告 |
| 🎯 | 仅分类事件 |
| ⚡ | 检测 + 分类都做过 |
| ○ | 空状态（不显示在结果面板） |

#### 交互操作

| 操作 | 效果 |
|------|------|
| 点击广告段 | 播放该段音频 |
| **Ctrl+点击** 广告段 | 选中/取消选中（黄色边框） |
| 点击事件轨道 | 选中文件（查看频谱） |

#### 事件轨道配色

| 颜色 | 标签示例 |
|------|----------|
| 浅蓝 (100,200,255) | 第 1 个出现的标签 |
| 浅绿 (150,255,150) | 第 2 个出现的标签 |
| 橙黄 (255,180,100) | 第 3 个出现的标签 |
| 淡紫 (200,150,255) | 第 4 个出现的标签 |
| 青 (100,255,220) | 第 5 个出现的标签 |
| 粉红 (255,140,180) | 第 6 个出现的标签 |

> 标签颜色由**首次出现顺序**分配，多个文件中相同标签保持同色（图例统一说明）。

#### 事件轨道绘制细节（与源码对齐）

主音频条和事件轨道的尺寸/颜色有精确分工：

| 元素 | 高度 | 背景色 | 说明 |
|------|------|--------|------|
| 主音频条 | **28px** | `(30,30,35)` 深灰 | 广告段实色块 |
| 事件轨道 | **20px** | `(22,26,32)` 更深灰 | 事件段边框 + 低 alpha 填充 |
| 时间刻度 | **20px** | 透明 | 只画刻度线和数字 |

**事件段文字显示阈值**：

| 段宽度 | 显示内容 | 字体 | 颜色 |
|--------|----------|------|------|
| > 60px | `标签名 置信度%` | proportional 9.0 | WHITE |
| 25 ~ 60px | 仅 `置信度%` | proportional 8.0 | (200,200,200) 浅灰 |
| < 25px | **什么都不显示** | — | — |

> 窄段（< 25px）只有冷色调边框 + 低 alpha 填充（`from_rgba_unmultiplied(color, 50)`），无文字。

**文件标题行格式**（检测 + 分类后）：

```
[⚡] song.mp3  原始: 210.5s | 剩余: 180.0s | 3 广告段（已标记删除 0） | 5 事件 | 平均匹配度: 85%
[✓] pod.wav   原始: 300.0s | 剩余: 270.0s | 2 广告段（已标记删除 2）
[🎯] raw.wav   原始: 120.0s | 5 事件
```

**时间刻度规则**：

| 总时长 | 刻度数 | 间距 |
|--------|--------|------|
| ≤ 300s | **5** | `duration * i / 5` |
| > 300s | **10** | `duration * i / 10` |

刻度线 3px 短划线 + 灰色 (140,140,140) 小字号标注原始时间。

**广告段匹配度文字阈值**：段宽 > 50px 才显示 `{start}-{end}s {score}%`，否则只显示时间。

**平均匹配度**：只算 `score > 0` 的有效广告段均值；没有可用 score 时显示为空。

#### 结果面板标题栏控件

文件列表头部水平排列：

| 控件 | 默认 | 作用 |
|------|------|------|
| 标题文本 | 自动生成 | 随数据变化显示 `N 文件, M 广告段, K 事件` |
| ☑ 频谱 | 未勾选 | 选中文件后在下方显示能量包络 + Mel 频谱 |
| ☑ 按匹配度排序 | 未勾选 | 匹配度高的文件排前面，未知匹配度（score=0）排最后 |
| 匹配度图例 | — | ●深红 ≥90% ●红 80-90% ●橙 60-80% ●黄 <60% |
| 🎯事件图例 | 条件显示 | 仅当有事件分类结果时显示 `▢ 纯音 ▢ 噪声 ...` |

#### 选中/播放视觉反馈

当用户点击广告段时，三个层同时变化：

| 状态 | 视觉效果 |
|------|----------|
| 正在播放当前段 | 段变白底边框 + alpha=255（最亮） |
| 其他段（同文件） | alpha=50（几乎看不见） |
| Ctrl+点击选中 | 段变黄框 `(200,200,50)` stroke 2px |

| 状态图标 | 颜色 | 含义 |
|----------|------|------|

### 3.5 阈值设置面板（独立窗口）

点工具栏右侧 `阈值设置` 按钮弹出独立可关闭窗口：

```
┌─────────── 阈值设置 ──────────────┐
│ 最小广告长度   [  0 ▲▼ ] 秒        │
│ 最小出现次数   [  2 ▲▼ ]           │
│ 极高置信度阈值 [0.90 ▲▼ ]          │
│ 高置信度阈值   [0.80 ▲▼ ]          │
│ 低置信度阈值   [0.60 ▲▼ ]          │
│                                   │
│  [恢复默认]  修改后立即生效...      │
└───────────────────────────────────┘
```

| 参数 | 默认 | 范围 | 作用 |
|------|------|------|------|
| 最小广告长度 | 0 | 0 ~ 60 秒 | **0 = 不限制**；低于此长度的广告段不显示、不参与裁剪 |
| 最小出现次数 | 2 | 2 ~ 10 | 广告至少要在多少个文件中重复出现（单次出现的"疑似"片段被过滤） |
| 极高置信度阈值 | 0.90 | 高阈值 ~ 1.0 | ≥ 此值 → 广告段显示**深红色** |
| 高置信度阈值 | 0.80 | 低阈值 ~ 极高阈值 | ≥ 此值 → **红色**；达到极高阈值则为**深红** |
| 低置信度阈值 | 0.60 | 0.0 ~ 高阈值 | < 此值 → **黄色**；介于两者之间 → **橙色** |

**联动约束**：三档阈值互相限制（低 ≤ 高 ≤ 极高），拖动时其余阈值可用范围会自动收紧。

**行为细节**：
- ✅ 修改**立即生效**（无需点"应用"）
- ⚠️ 阈值变化时，之前选中的广告段会被清空（避免序号错位）
- `恢复默认` → 一键回到出厂配置

### 3.5.1 按匹配度选择窗口

点工具栏 `按匹配度选择` 弹出：

```
┌────────── 按匹配度选择 ──────────┐
│ 匹配度范围                        │
│  ( ) 极高置信度（≥ 90%）          │
│  ( ) 高置信度（80% – 90%）        │
│  (•) 中等置信度（60% – 80%）      │
│  ( ) 低置信度（< 60%）            │
│  ( ) 自定义下限  [0.70 ─────]     │
│                                   │
│ 作用范围                          │
│  (•) 全部文件  ( ) 仅当前选中文件 │
│                                   │
│ 匹配到 N 个广告段                 │
│  [选择匹配段] [取消选择匹配段]    │
└───────────────────────────────────┘
```

- 选中的段在时间轴上显示黄色边框，工具栏按钮变为 `删除所选 (N)`
- 点 `删除所选` 会把它们标记为删除：色块压暗并画红色斜线，**点保存后才真正从音频中剪掉，并把前后音频拼接起来**
- 未标记的广告段在保存时保持原样
- 标记不改变检测结果；阈值变化时会清空选择与标记，避免序号错位
- 旧版结果（`score = 0`）的匹配度未知，不参与任何筛选

| 子图 | 数据源 | 说明 |
|------|--------|------|
| 能量包络 | STFT 每帧全频幅度和的峰值 | 32px 高；横向对齐主音频条；直观看到哪里"声音大" |
| Mel 频谱 | MFCC 同 40 维 Mel 滤波器组 | 84px 高；时间轴横向，**低频在下、高频在上**；与人耳感知一致 |

#### 热力配色（4 个停靠点）

```

(深蓝)  (紫)    (橙红)   (浅黄)

```

#### 广告段叠加

每个满足 `count > 1` 的广告段在能量包络和 Mel 频谱上同时叠加：
- 半透明红色填充（alpha ≈ 16%）
- 红色实线边框

#### 缓存机制

FFT 结果来自检测阶段写入磁盘的缓存。GUI 维护 VizCache：
- 键：**文件路径 + 文件修改时间 + 面板宽度**
- 命中时只克隆内部 Arc 纹理句柄（零开销）
- 文件更新后自动重建

#### 常见提示

**频谱缓存不可用？** 显示"频谱缓存不可用，请重新执行检测后再查看" → 点 `检测广告` 跑一遍就会生成缓存。HPSS 会使 CACHE_VERSION 升到 2，旧缓存自动失效，需要重新检测。

### 3.7 播放功能（广告段预览）

GUI **只支持广告段预览播放**（不支持整文件/音频条随便拖进度）。底层用 `rodio` crate 解码并按段截取。

#### 触发方式

| 操作 | 效果 |
|------|------|
| **点击**中央结果面板的某个广告段 | 开始播放该段（`playing_file` = 当前文件索引, `playing_ad` = 段索引） |
| **再次点击同一个段** | 停止播放 |
| **点击另一个广告段** | 先让旧播放线程退出 → 等 150ms → 开始新段播放（不会叠加） |

#### 播放时长计算

检测模块输出的 `Range.begin/end` 单位是 **0.1 秒**（整数）。播放时转换：

```rust
let start_secs = ad.begin as f64 / 10.0;
let end_secs   = ad.end   as f64 / 10.0;
let duration   = end_secs - start_secs;

source.skip_duration(start_secs).take_duration(duration)
```

#### 状态反馈

| 状态 | 底部状态栏显示 |
|------|----------------|
| 正在播放 | `正在播放: song_01.mp3 广告2` |
| 播放完自动停 | 恢复 `就绪` |
| 手动停止 | `播放已停止` |

#### 停止机制

后台线程以 **100ms 轮询** `stop_flag`（`Arc<Mutex<bool>>`）：

```
播放线程 (thread::spawn):
  for i in 0..max_checks {        // max_checks ≈ duration_secs × 10 + 10
      sleep(100ms)
      if *stop_flag { sink.stop(); return; }    ← 主动点击其他段或停止按钮
      if sink.empty() { break; }                ← 自然播放完
  }
```

旧播放被抢占时：
1. `stop_flag = true` → 旧线程下一次 100ms 轮询时退出
2. 主线程 `sleep(150ms)` 等旧线程退出
3. `stop_flag = false` + 启动新线程

#### 局限性

| 限制 | 说明 |
|------|------|
| 仅广告段 | 无法随便播放非广告区域，需要整文件听请用外部播放器 |
| 无进度条 | GUI 没有显示当前播放位置，只能靠耳朵听 |
| 无音量控制 | 用系统默认音量（rodio 走 `OutputStream::try_default()`） |
| 无暂停/继续 | 只有"播"和"停"两个状态，点击就是 toggle |
| 单播 | 同一时刻只有一个段在播，多文件多段不会叠加 |
| 音频输出依赖系统 | 需要设备有可用的 `OutputStream`；无头服务器/容器里会打印 `无法打开音频输出` 并静默失败 |

### 3.8 保存选项（裁剪写盘）

保存流程在**后台线程**执行，不阻塞 UI。工具栏有两个相关控件：

```
┌──────────────────────────────────────────────────────────────────────┐
│ ... │ ☐ 覆盖原文件 │ 保存 (3 个文件) │ ...                          │
└──────────────────────────────────────────────────────────────────────┘
```

#### 两种保存模式

| 模式 | 工具栏 checkbox | 输出路径 | 底层函数 |
|------|-----------------|----------|----------|
| 覆盖原文件 | ☑ 勾选 | 原始路径 `file.path` | `pipeline::overwrite_file` |
| 输出到新目录 | ☐ 未勾选（默认） | FileDialog 选目录 → `目录/file.name` | `pipeline::cut_file` |

**非覆盖模式流程**：点保存 → 弹出"选择输出目录" FileDialog → 选目录后逐个文件写入 → 完成。如果用户取消 FileDialog，**直接返回**（不报错，静默忽略）。

#### 参与保存的文件过滤

只有满足以下条件的文件才进入保存队列：

```rust
f.detected && !f.marked_for_deletion.is_empty()
```

| 条件 | 说明 |
|------|------|
| `detected == true` | 至少跑过一次广告检测 |
| `marked_for_deletion` 非空 | 至少有一个广告段被「删除所选」标记（索引基于有效广告段） |

工具栏保存按钮上的数字**实时计算**：每次阈值变化后自动更新 `保存 (N 个文件)` 里的 N。没有候选文件时按钮仍可点（但后台会输出"没有需要保存的文件"）。

#### 裁剪逻辑

```
原始: [广告段1] [保留区] [广告段2] [保留区] [广告段3] [保留区N]
标记:    ✓                  ✗                  ✓
输出: [保留区] + [广告段2] + [保留区] + ... + [保留区N]
```

具体实现：`effective_ads(thresholds)` 取有效广告段 → 按 `marked_for_deletion` 里的索引挑出被标记的段 → `reverse_range` 计算剩余区间（补集） → 拼接写出。未标记的广告段会被保留。

#### 进度与状态反馈

后台线程逐文件处理，状态条实时更新：

```
处理中:  [1/3] 处理: song_01.mp3        ← 状态文本
完成:    保存完成！已覆盖原文件 (3 个文件)
         保存完成！输出目录: /tmp/cut (3 个文件)
失败:    保存结束：成功 2 个，失败 1 个（song_02.mp3: I/O 错误）
```

保存成功后，该文件的 `needs_save` 标记置 false 并清空 `marked_for_deletion`，下次保存不会重复处理。

#### 保存按钮的禁用条件

`can_save = files_to_save > 0 && !is_processing`：

| 条件 | 禁用 | 原因 |
|------|------|------|
| 无有效广告段 | ✅ 数字为 0 | 没东西可裁剪 |
| 正在检测/分类中 | ✅ | 防并发锁冲突 |
| 正在播放中 | ❌ | 可以边听边保存 |

#### 注意事项

| 注意 | 说明 |
|------|------|
| 阈值影响保存 | 改阈值设置面板的 min_length / min_count → 有效广告段列表变化 → 保存队列自动重算 |
| Ctrl+点击只是选中 | 选中广告段不影响保存逻辑（保存用的是 `effective_ads(thresholds)`），选段只用于**视觉高亮** |
| 并发安全 | 保存用后台 `thread::spawn`，共享状态通过 `Arc<Mutex<AppState>>`，不会阻塞 UI 主线程 |
| 同文件名覆盖 | 非覆盖模式下，如果两个文件同名（来自不同目录），选同输出目录会互相覆盖。建议分目录保存 |

## 5. CLI 训练事件分类模型

GUI 的 🎯 分类事件功能需要先训练 `.mcrf` 模型文件。用 CLI 训练：

```bash
# 1. 准备数据列表 data.txt（每行: "音频路径 标签"）
#    例如:
#    /data/podcast_001.wav 纯音
#    /data/podcast_002.wav 纯音
#    /data/jingle_a.wav 噪声
#    /data/jingle_b.wav 噪声

# 2. 训练（自动 2s 窗口扩展）
mp3cutad-cli train \
  -d data.txt \
  -o model.mcrf \
  --trees 200 \
  --test-split 0.2 \
  --seed 42

# 输出示例：
# 窗口扩展后样本: 90
# 测试集评估:
# 标签       精确率   召回率    F1
# 噪声       1.00    1.00    1.00
# 纯音       1.00    1.00    1.00

# 3. GUI 中加载 model.mcrf 即可使用
```

### train 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `-d, --data-list` | 必填 | 数据列表文件 |
| `-o, --output` | 必填 | 输出 `.mcrf` 路径 |
| `--trees` | 100 | 随机森林树数（越多越准越慢） |
| `--max-depth` | 32 | 每棵树最大深度 |
| `--test-split` | 0.2 | 测试集比例 |
| `--seed` | 42 | 随机种子（保证可复现） |

### 模型文件格式 `.mcrf`

```
┌─────────────┐
│ MCRF (magic) │  4 bytes
├─────────────┤
│ version=1    │  4 bytes
├─────────────┤
│ bincode payload:                 │
│   feature_dim   u32              │
│   labels        Vec<String>      │  ["纯音", "噪声", ...]
│   scaler_mean   Vec<f64> (128)   │  StandardScaler 均值
│   scaler_std    Vec<f64> (128)   │  StandardScaler 标准差
│   window_sec    f64 = 2.0        │  滑窗宽度
│   hop_sec       f64 = 1.0        │  滑窗步长
│   forest        Forest (n 棵 CART)│  bincode 序列化
└─────────────┴───────────────────┘
```

加载时做 **七重校验**：magic → version → feature_dim → labels 非空 → scaler 维度匹配 → 森林节点总数 → window_sec 合理范围。

## 6. 架构说明

### 三层分离

```
┌─────────────────────────────────┐
│  GUI / CLI        界面层         │  egui / clap
├─────────────────────────────────┤
│  core::detect     检测层         │  广告段 LSH + Viterbi
│  core::classify   分类层        │  事件 RF + 滑窗
│  core::separation 分离层        │  HPSS 中值滤波
├─────────────────────────────────┤
│  core::fft        基础层         │  STFT / FFT
│  core::segfeat    特征层         │  128D 统计特征
│  core::forest     模型层         │  随机森林
│  core::model      持久层         │  .mcrf 读写
└─────────────────────────────────┘
```

### 三期集成关系

| 阶段 | 模块 | 调用链 |
|------|------|--------|
| 一期 事件分类 | classify → forest → segfeat | `samples → 2s 窗口 → 128D → RF → majority vote` |
| 二期 GUI 集成 | menu → state → results | `start_classification → classify_file_with_progress → 事件轨道绘制` |
| 三期 HPSS 分离 | separation → detect | `decoded → percussive_track → fft::process_wav → LSH detect` |

## 7. 常见问题

**Q: 分类事件后置信度都是 0.55 以下，结果面板显示"未检测到事件"？**
A: 默认 `confidence_threshold=0.55` 较高。GUI 暂未暴露滑块，可改 `AppState.classify_confidence` 默认值或 CLI `classify --confidence 0.45` 验证模型质量。

**Q: HPSS 分离后检测速度变慢？**
A: 正常现象。每个文件需额外做一次 HPSS（≈2× STFT + 2× 中值滤波 + 1× iSTFT）。通常增加 2-3 倍预处理时间。

**Q: 旧检测结果文件还能用吗？**
A: 可以。广告段检测流程的 Range 格式没变。但 HPSS 启用后 CACHE_VERSION 从 1 升到 2，FFT 缓存会自动失效（下次检测重新计算）。

**Q: 事件分类标签能自定义吗？**
A: 标签由训练数据的 data.txt 决定。GUI 里事件轨道按**首次出现顺序**分配颜色，相同标签跨文件保持同色。

**Q: 模型文件损坏会怎样？**
A: GUI 选模型时即时 load_model 验证，七重校验任何一项失败都会弹错误提示（不会默默用坏模型）。
